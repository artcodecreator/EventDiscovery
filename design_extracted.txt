Introduction of Design Document
This Design Document specifies the architecture, components, interfaces, and data design for the Event Management System web platform. It is intended to guide developers in implementing a secure, user-friendly, and robust event management solution that also supports venue booking and attendance tracking features. The document defines the system’s structure through diagrams and specifications to ensure clarity and alignment with the requirements described in the SRS.
Objectives:
Define architecture and components.
Provide visual diagrams (ERD, Class, Architecture).
Ensure alignment with VU Process Model.
Serve as a reference during coding, testing, and deployment.

The Event Discovery & Community Engagement Platform is a web-based system that allows:
Guest Users and Registered Users to browse, search, and explore events, view event details, and RSVP or register for events. 
Registered Users to save favorite events, submit reviews and ratings, and manage their profiles and event participation. 
Event Organizers (Registered Users) to submit and manage event listings for approval by the system. 
Administrators to manage events, approve or reject submitted events, manage users and categories, and monitor overall platform activities. 
Integration of interactive maps, event filtering, and automated notifications to enhance event discovery and user engagement.
Primary Users
Guest User 
Registered User 
Event Organizer 
Administrator (Admin / Super Admin) 
Key Features
Event browsing with interactive map and list view 
Event search and category-based filtering 
Event detail pages with images, location, and full description 
RSVP and event registration system 
Favorite/bookmark events for registered users 
User reviews and ratings for events 
Event submission and approval workflow 
Featured events section on homepage 
Real-time synchronization between map and list views 
Role-based access control (Guest, User, Admin) 
Admin dashboard for event, user, and category management 
Seeded/demo event data for testing and demonstration

Architecture Design Diagram
3-Tier Architecture (Modern Web Stack)
Tiers
1. Presentation Layer (Frontend)
Purpose:Handles user interface, user interactions, and client-side rendering. Provides responsive event browsing, map visualization, and user engagement features. 
Technologies: 
Next.js (React-based framework) 
Tailwind CSS / Styled Components 
Shadcn UI / Material-UI 
Leaflet.js (for maps) 
NextAuth.js (authentication handling) 
2. Application Layer (Business Logic Layer)
Purpose:Manages core application logic, workflows, authentication, authorization, and API handling. Processes event submissions, approvals, RSVPs, and user-specific operations. 
Technologies: 
Strapi v5 (Headless CMS) 
Custom Controllers & Services (Strapi APIs) 
JWT-based Authentication 
RESTful API / GraphQL API 
3. Data Layer (Backend / Data Access Layer)
Purpose:Handles data storage, retrieval, and persistence. Ensures efficient querying and management of events, users, registrations, and related entities. 
Technologies: 
PostgreSQL / MySQL (Database) 
Strapi ORM / Query Engine 
Cloud Storage (AWS S3 / Cloudinary for media files) 
Key Notes
Clear separation of concerns between UI, logic, and data 
Scalable headless architecture using Next.js + Strapi 
Secure authentication and role-based access control 
API-driven communication between frontend and backend 
Optimized for performance, SEO, and responsiveness
